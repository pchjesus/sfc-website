# SFC v2.8.4 — 탭별 시그니처 모션 재설계·실행 검수

작성: 2026-11-26. 브랜치: `preview/sfc-v2.8.4-page-signatures`. **소유자 검수 전 main 병합·GitHub Pages 배포 금지.**

## 왜 다시 바꾸었나

v2.8.2는 화면을 빠르게 만들면서 입장 투명도를 실제로 보존하지 못했다. v2.8.3은 그 문제를 바로잡았으나 모든 탭에 교차 이동/순차 나타나기라는 공통 포맷을 적용하고, 일부 상단 문구 완료까지 약 1.8~2.4초가 소요되어 답답했다. **문제는 속도만이 아니라 공간·콘텐츠의 의미를 모션에 반영하지 않은 점**이다.

v2.8.4는 속도를 **v2.8.2와 v2.8.3의 중간**으로 조절하면서 전환 종류를 분리한다.

| 화면 | 무엇을 보여주는가 | 사용한 물리적 동작 | 실제 코드/검수 표식 |
|---|---|---|---|
| Home | 사진·타이포로 브랜드를 기억시키는 첫 장면 | 이미지의 노출(밝기) 정착, 글자는 아래에서 마스크가 열림, CTA만 작은 상승. 3장 원본 사진 그대로 | `photographic-typographic-mask`, `typeMask`, `hero-photo.active` |
| About | 학회 소개와 기업분석의 사고 순서 | 소개 사진/영역은 **중앙에서 확장**; 승인된 소개 3줄은 왼쪽에서 인쇄. Observe: 관계선, Analyze: 막대 기준선, Value: 두 추정 경로, Defend: 보고서 지면 | `diagram-connect-and-column-reveal`, `sweep`, `stage(index)` |
| Research | 검색하고, 필터·정렬하며 자료를 비교 | 검색 도구는 중앙에서 개방, 결과 행은 **위에서 아래로 펼침**, list/grid는 실제 DOM 항목의 위치 보간 FLIP | `workspace-expand-and-spatial-flip`, `sweep`, `dropReveal`, `SFC_MOTION.transition` |
| Activities | 15주 학습 단계와 주차 자료를 순서대로 읽기 | 탭 네 개가 각자의 자리에서 확장, 커리큘럼 행은 **위에서 아래로 개방**. 주차 행의 좌표나 내용 구조 변형 없음 | `fifteen-week-timeline-drop`, `dropReveal` |
| People | 구성원/직책/담당 업무를 찾아 읽는 명단 | 기존 모든 업무 내용을 즉시 DOM에 유지하면서 인물 이름·직책을 **인쇄되는 방향으로 공개**. 카드가 양쪽에서 날아오지 않음 | `typographic-index-print`, `ink` |
| Recruitment | 모집 상태/4개 주요 사실/지원 행동 | 모집 정보 2×2가 **중심에서 퍼지고**, 지원 안내가 아래로 펼쳐짐, 4단계 절차는 순서대로 표면 강조. 지원 완료로 오인시키는 애니메이션 없음 | `fact-grid-center-bloom`, `bloom`, `processSteps` |
| Updates | 발행된 공지·활동·리서치 소식을 훑기 | 뉴스 헤더는 **왼쪽에서 인쇄**, 게시글 본문은 **종이가 아래에서 위로 펼쳐지듯** 공개됨. Research의 위→아래 자료 개방이나 People의 수평 명단 인쇄와 구별. 실제 검색 결과는 즉시 표시 | `publication-line-ink`, `ink` |

### 조정한 공통 속도

| 영역 | v2.8.3 | v2.8.4 |
|---|---|---|
| 전체 페이지 광학적 정착 | 1,420ms | **1,100ms** |
| 핵심 헤딩·콘텐츠 등장 | 약 1,400–1,850ms | **약 970–1,280ms** |
| 사진 크로스페이드 | 1,700ms | **1,360ms** |
| 슬라이더 본문 교체 | 1,490ms | **930ms** |
| 목록 FLIP 재배치 | 780ms | **670ms** |
| About 단계별 SVG | 최대 약 1,620ms | **약 790–950ms** |
| 스크롤 일반 등장 | 1,400–1,550ms | **1,150–1,210ms** |

중요: WAAPI `fill:"backwards"`를 유지하므로 지연 중 잘못 완성된 문구가 보이지 않는다. 시작 불투명도는 0에서 시작하며 전체 지속시간 동안 상승한다. 전역적으로 스크롤을 강제로 이동시키지 않는다. `prefers-reduced-motion`은 비필수 모션을 중단한다. 사진/텍스트/아래로 읽는 기존 정보 위계는 바꾸지 않았다.

### 유지한 사용자 승인 결정

- Home 기존 사진과 영문 헤드라인·CTA; 별도 '상명대학교 경영학부 · 기업재무분석 학술동아리' 히어로 문구 **재추가 금지**.
- About 사용자 승인 문구 정확한 세 줄과 현재 레이아웃.
- Research `DEMO / EQUITY RESEARCH` 인접 표시 및 실발행 여부 고지.
- Activities 기존 구성·15주 상세·단계/주차 자료, v2.8.2에서 교정한 타 탭 대비 비례 유지.
- People 인물/직책/담당 업무 즉시 읽을 수 있는 정보 구조.
- Recruitment 상태 `planned/open/closed`, 실제 공고·지원 파일·링크, 네 단계의 공개 정보.
- Updates 실제 공개 소식, 최신순, 빈 데이터/오류/재시도.
- 푸터 상명대학교 로고, CMS/Studio/Auth/RLS/Storage 계약 미변경.

## 실제 검증 계약

1. `npm test`: 7개 시그니처 값의 유일성, 마스크/센터 확장/수직 리빌/인쇄/분석 경로의 서로 다른 첫 키프레임, 속도 최대 1,360ms, `fill:backwards`, 이전 애니메이션 취소와 `prefers-reduced-motion`.
2. Chromium: 7개 공개 탭과 각 요소의 `getAnimations()[0].effect.getKeyframes()`를 검증. Activities 1440/768/390/360px 제목 크기와 모바일 넘침/필터 방향/실제 행 유지. Studio 동작은 mock DB 기반 검증.
3. 녹화: 7개 탭, Activities 모바일, 모바일 탭 이동 총 **9개 WebM** + 전체 스크린샷. Home/About/Activities 첫 화면은 **120·520·1,050·1,700ms** 4단계 PNG를 추가 생성.
4. 데이터 무결성: 실 Supabase Auth/RLS/Storage 검증과 연결하지 않았으므로 **NOT RUN**. Codex 전체 기능 감사 역시 사용자의 별도 승인 다음 단계.
