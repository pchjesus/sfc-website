## 1. 목표 및 현재 기능

운영진이 보고서, 공지, 활동 소식을 작성할 때 문서 편집기처럼 편리하게 사용하되, 실수로 게시하거나 입력을 잃지 않도록 한다. 기존 Studio를 유지하며 새 CMS/대형 편집기 의존성 도입을 기본값으로 삼지 않는다. 기존 공개 디자인/모션에 영향 없음.

`js/cms-admin.js`, `admin.html` 기준: 400ms 지연 계정+작업 ID별 sessionStorage 복구 스냅샷 및 복구 선택, 2.6초 debounce 서버 자동저장(신규/초안, 유효 제목 3자 및 본문 1자 이상, 선택 파일 있을 경우 건너뜀), 수동 임시저장, updated_at CAS, 입력 지문 비교, 미저장 이동 경고, 게시·예약·비공개·휴지통·수정 이력·미리보기·빈 본문 연구 템플릿. 서버 자동저장은 이미 공개된 글에는 적용되지 않으며, 파일 자체와 탭 종료 후 복구는 보장하지 않는다. 목록은 최신 수정 300건 제한 내 검색·유형·상태·정렬 지원. 제목/목록 툴바, 글자 수, 집중 모드, sticky 저장, 모바일 폭 미리보기 및 간단한 게시 확인 구현. Reader 완전 일치·TOC·undo/redo·이력/충돌 비교·상세 검수는 미완료. v2.9는 사이트/모집 CAS 및 구조화 폼 잠금을 개선했으나 People/Activities의 cross-admin CAS는 미구현.

### S0 — 자동저장 및 복구

- 기존 debounce 자동저장(2.6초 기준)을 활용한다. 입력 중 불필요한 요청을 줄이고 최신 snapshot만 순차 저장. 명시적 수동 임시저장 버튼은 유지하며 Ctrl/Cmd+S는 편집 중 임시저장/안전한 작업본 저장만 수행(게시 금지); 입력 포커스 및 접근성 검증.
- 고정된 가벼운 상태 영역: '아직 저장되지 않음' → '저장 중' → '서버 저장 완료 HH:mm:ss' 또는 '이 기기에만 저장 / 연결 끊김 / 저장 실패 / 충돌'. 서버 응답 확인 전 성공 표시 금지. 마지막 로컬 및 서버 저장 시각 구분.
- 제목/본문이 비어 있는 미완성 글도 로컬 복구 대상. 서버 검증 조건 완화는 DB 제약과 검수 영향 확인 후 결정.
- 계정+글 ID+신규 draft 고유 ID별 복구본 분리, base updated_at/저장 시각 포함. 세션 유지 복구를 기본으로 보완하고, 탭 종료 후 복구가 필요하면 명시적인 신뢰 기기 옵션 및 IndexedDB 등 비교. 민감 문서의 장기 로컬 저장은 기본 off; 로그아웃 시 데이터 제거/보존 정책과 공용 PC 경고, 만료/용량/브라우저 저장 차단 처리. 파일 bytes 자동 백업은 기본 금지; 선택 파일은 재선택 안내.
- 자동저장 실패 시 입력 보존, 연결 복구 후 안전한 재시도(중복 생성 방지), CAS 충돌 시 자동 덮어쓰기·무조건 재시도 금지. '서버 최신본 보기 / 내 작업 복사 / 비교 후 수동 병합' 제공. 변경 없는 반복 저장·revision 증식 최소화.
- 게시 중 변경·연속 클릭·로그아웃·메뉴 전환·느린 응답에 대한 폼 잠금 또는 입력 snapshot/세대 검증. 오래된 비동기 응답이 다른 글에 적용되지 않게 테스트. 초안 복구 후 원격 공개본 상태가 바뀐 경우 경고.
- 게시물 저장과 파일 업로드 분리 표시. 현재 public sfc-media에는 공개 승인 최종본만 등록. draft/예약 파일의 직접 URL 노출 경고 및 별도 비공개 staging 준비. 공개 승인 미확인 파일은 업로드하지 않는다. 미리보기는 가능하면 승인된 로컬 파일의 object URL(해제 처리), 공개 전 URL 발급 금지.
- 비공개 전환은 게시물만 숨기고 이미 공개된 파일 URL 회수를 보장하지 않음을 설명.

### S1 — 작성과 탐색

- 레이아웃: 기존 사이드바 + 본문 편집기 유지. 작은 상단 바(글 유형/상태/저장 시각), 본문 편집 영역, 하단 또는 상단 sticky 액션(미리보기/임시저장/게시). 모바일 한 열 및 가상 키보드/스크롤 검증. 설정은 보조 영역; 핵심 입력을 지나치게 접지 않는다.
- 가벼운 편집 툴바: 제목/소제목, 굵게(렌더러 지원 여부 먼저 확인), 목록, 링크/인용 등 실제 안전 렌더러 지원 문법만. 선택영역 적용, Undo/Redo 보존, 키보드와 도움말. 원시 HTML 실행 금지. 표/이미지/차트는 원본 보고서 요구와 XSS 검토 후 추가; 필요 없는 WYSIWYG 전면 교체 금지.
- 글자 수(제목 180/요약 350/본문 50,000 등 현행 제한), 요약 누락·제목·첨부 파일 검증, 작성 중 비차단 안내. 본문 붙여넣기 시 텍스트 및 줄바꿈 보존, 자동 문체 변환 금지.
- 보고서 유형별 템플릿(기업분석/산업/거시), 공지·활동 템플릿은 실제 수요 확인 후. 빈 본문 삽입 또는 명시적 확인; 템플릿 예시 문구가 공식 결과로 공개되지 않도록 검수.
- Reader와 같은 렌더러/메타/목차를 사용한 미리보기, 모바일 폭 전환, PDF 로컬 미리보기/열기. 미리보기에는 저장하지 않은 편집 상태 반영. 운영 공개 주소에 draft 노출 금지. 외부 PDF URL은 승인된 공개 자료만.
- 목록: 검색(제목/종류/저자), 기존 상태 필터와 최근 수정순, 최근 작업 재개, 저장된 초안의 제목/요약/시각, 필요시 정렬/페이지네이션. 300건 상한 확대는 실제 규모와 서버 비용 확인 후. 복제 기능은 새 draft 생성 및 이전 공개 허가/예약/파일 자동 승계 금지.
- 발행 확인 창: 글 제목, 대상 영역, 즉시/예약(KST 및 입력 시간대 명시), 공개 파일 여부, 필수 메타데이터 누락, 공개 허가 확인. '임시저장'과 '게시' 시각적으로 구분. 실제 콘텐츠 발행은 명시적인 승인과 클릭만.

### S2 — 검수 및 편집 운영

- 공개된 현재 버전과 편집 중 작업본 분리(스키마/별도 작업본 설계 검토). 자동저장/수동 저장/리뷰는 공개본을 바꾸지 않는다. 작업본이 공개본의 base version과 다르면 비교·수동 해결. 게시/예약 발행시 원자적 전환 또는 명확한 보상 절차. 현재 구조에서 공개본을 draft로 내려 작업하는 방식은 대체 수단일 뿐.
- 검수 체크리스트: 저자·원본 작성일·발행일·공개 허가·출처·수치·PDF·모바일. Draft/Review/Ready/Published 상태는 내부 작업흐름으로 시작, 현재 최대 3인 superadmin 권한을 임의 변경하지 않는다.
- 이력: 변경 전후 텍스트/메타/첨부 비교, 누가 언제 저장·발행했는지 표시, 이전 버전을 작업본에 불러온 후 명시적 저장. 자동저장 스냅샷 보존 주기/비용은 실제 운영량에 따라 결정. 복원 전 승인 및 현재본 보존.
- 파일 관리: 파일명·크기·형식·검수/공개 상태·참조 게시물/리비전·해시·업로드 시각. private staging + 공개 승인 후 배포 또는 권한 기반 제공 비교. MIME/확장자/파일 내용 검사, 20 MiB 현행 제한, 실패/재시도 및 고아 파일 탐지. 삭제는 참조 검사와 dry-run, 소유자 승인, 백업 후 수행.
- People/Activities updated_at 및 CAS, 사이트/모집 기존 CAS 유지. 데이터와 미디어 manifest/체크섬 백업, 분리 환경 복원 연습. 로그에는 비밀번호/토큰/개인 지원서를 넣지 않는다.

### S3 — 수요 기반 편의 기능

단축키 도움말, 집중 작성 모드, 여러 임시글 작업 전환, 글 종류별 최근 템플릿, 확정된 공지의 반복 작성, 검색 및 예약 달력, 인수인계용 운영 요약. 대량 편집/삭제, 드래그 정렬, 알림, 역할 계층은 필요성이 증명된 경우 별도 검토. 대량 변경은 사전 미리보기와 되돌리기 정책 필수.
