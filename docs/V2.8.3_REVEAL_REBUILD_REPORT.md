# SFC v2.8.3 — 투명도 기반 모션 재설계 및 검수 기록

작성: 2026-11-26. 적용 범위: **preview/sfc-v2.8.3-reveal-rebuild 브랜치**. 공개 main/GitHub Pages 배포 **하지 않음**.

## 문제의 원인

이전 v2.8.2의 새 진입 모션은 실제로 불투명도 `0.48–0.76`에서 시작했고, 초기 구간에 변화가 집중된 `cubic-bezier(.16,1,.3,1)`을 사용했다. 더 심각하게는 WAAPI `fill:"none"`으로 지연 중 시작 프레임을 유지하지 않아 **움직이기 전에 이미 완성된 요소가 보일 수 있었다**. 실제 duration을 길게 입력했지만 시각적으로 부드러운 점진적 등장 대신 작은 위치 이동처럼 보인 이유다.

v2.7은 상대적으로 `opacity:.28/.3`, 780~950ms, `fill:"backwards"`을 사용했다. 이번 재작업은 그 초기 투명도 원칙을 복원하되 한 단계 더 깊고 천천히 들어오는 장면 조립 모션으로 발전시켰다.

## 이번 변경 — 하나의 모션 언어, 탭별 고유 공간 구성

**공통**
- 모든 중요한 컨텐츠의 새 등장 시작점: `opacity:0`.
- 주요 타이포·패널의 투명도 단계: `0 → .035(14%) → .20(38%) → .68(73%) → .94(93%) → 1`.
- 가감속 `cubic-bezier(.42,0,.58,1)`, 전형적인 빠른 ease-out 대신 전 구간에 걸친 광학적 페이드.
- **`fill:"backwards"` 필수**: 지연 시간에도 원래 UI를 미리 보여주지 않고 투명한 첫 프레임 유지. 종료 시 완성된 원래 DOM 스타일로 복귀.
- 전체 화면은 1420ms에 걸쳐 opacity .06→1로 점진적 정착, 내부 계층은 1400~1850ms + 비선형 시간차. 탭 왕복 시 동일한 원칙으로 재등장, 기존 모션 cancel.
- 상호작용/상태/모집 가능 여부는 DOM에 즉시 반영. 실제 본문을 삭제·아코디언으로 추가 가림하지 않음. `prefers-reduced-motion` 대응 그대로.
- 목록/정렬 reflow 780ms. Home 사진 1700ms crossfade / 슬라이드 본문 1490ms 정착.
- 기존 디자인/사진/브랜드 색/본문/로고/권한/Studio/CMS 변경 없음.

| 탭 | 방향과 장면 완성 방식 |
|---|---|
| Home | 사진 자체의 밝은 정착, 위쪽 메타·왼쪽 제목·오른쪽 설명·아래 CTA/컨트롤이 서로 모이며 형성 |
| About | 소개 사진과 세 문장이 반대 방향에서 만나고, Observe/Analyze/Value/Defend 도식의 경로·막대·평가 비교·보고서 레이어가 각기 다른 순서로 서서히 그려짐 |
| Research | 검색 바와 컨트롤이 좌우에서 합류, 보고서 목록은 좌우 교차 입장과 780ms FLIP로 연결 |
| Activities | v2.8.2에서 수정한 제목·컨트롤·주차 글씨의 타 탭 대비 비례 유지. 4단계 컨트롤이 양쪽에서 모이고 주차 행은 opacity0 + clip-path로 서서히 개방 — 주차 위치·높이 자체는 변형하지 않음 |
| People | 이름/역할/책임 카드가 번갈아 좌우에서 부드럽게 합류. 실제 정보 구조 유지 |
| Recruitment | 소개/모집 사실 2×2가 반대편에서 합류, CTA와 네 단계 정보가 아래/양쪽에서 등장. 모집 상태 및 지원 버튼 동작은 즉시 |
| Updates | 제목/필터 반대편 합류, 실제 소식 목록은 엇갈린 방향의 긴 리빌. 빈 목록/에러는 꾸밈 없이 표시 |

## 실제 테스트와 시간 프레임

- 정적 소스검사 `npm test`: JavaScript 구문/버전/HTML/콘텐츠 및 지연 첫 프레임 opacity0/WAAPI fill 검사.
- Playwright: 최초 nav 전환에서 제목 computed `opacity`를 초기(120ms)/중간(770ms)/완료(2420ms) 측정. 기대: **초기 0~.12 미만, 중간 부분 노출, 마지막 .98 이상**. Activities도 같은 기준 확인. 수치가 실제 Chromium에서 검증되어야 PASS.
- Desktop Home/About/Activities 각각 t=180/820/1500/2400ms 프레임 PNG 총 12개. 공개 7탭 + Activities Mobile + Mobile navigation 동영상 9개.
- 전체 회귀 테스트: 공개 7개 탭·Research Reader/목록·Activities·People/Recruitment/Updates·기존 Studio 모의 데이터·화면 폭 1440~360px.
- **실제 Supabase Auth/RLS/Storage 보안 및 Codex 전체 감사는 수행하지 않음.** mock PASS와 구별.
