| 실적·신뢰 표현 | 7 | 실제/샘플 구분은 고지되지만, 홈 최상단 Featured에 시연 보고서가 강조됨 | **선명한 상태 구분** |

숫자는 실측 만족도나 Lighthouse 점수가 아니라 설계 검토를 위한 상대적 **주관적 가설**이다.

## 2. 잘한 것 — 되돌리지 말 것

1. 종교/기업 홈페이지처럼 보여도 '금융 리서치'에 적절한 고전적인 네이비·화이트 기본 톤; 코랄은 CTA와 상태 강조에만 부분 사용.
2. Home → About / Research / Activities / Recruitment의 깊지 않은 탐색 구조.
3. Research의 검색·섹터 필터·정렬·목록↔그리드·페이지네이션·빈 결과 복구; 실제 게시물과 Demo의 UI 일치.
4. People의 이름·역할·담당 업무 전부 노출, Recruitment의 네 단계 상시 노출. 이전의 중복된 세부 패널·강제 클릭을 부활시키지 말 것.
5. 실제 게시 자료와 예상 교육 일정·역할 예시 구분, 공개 열람 무로그인, 관리자 Studio 분리.
6. 기본적인 `prefers-reduced-motion` 분기, 영웅 슬라이드 일시정지, 페이지별 스크롤 상태, 연구 리더 TOC 등의 기반.

## 3. 개선 우선순위 — 무엇을 왜 바꿀까

### P0. 첫 화면에서 학회 정체성 명시

- 현재: 시적 영어 문구, 이미지를 바꾸는 3장 히어로. 정확한 '상명대학교 경영학부 기업재무분석 학술동아리'는 About에 명확.
- 단기: 히어로 안에 학회의 공식 성격 한 줄을 항상 노출하고, 본문/슬라이드 전환과 분리.
- 큰 개편 시: **브랜드 선언 + 실제 무엇을 하는지 + 어디서 시작할지** 3요소로 히어로를 새로 구성.
- 이유: 처음 온 학우·지도교수·기업 관계자는 이미지를 즐기기 전에 이곳이 무엇인지 판단한다.

### P0. 샘플 연구와 실제 성과의 혼동 여지 축소

- 현재: Home의 FEATURED는 DEMO/SAMPLE을 표시하지만 시각적 비중은 '대표 실적'에 준함.
- 단기: '실제 SFC 발행물이 아닌 UI 예시'를 제목 위와 본문에 더 직접 노출.
- 큰 개편 시: 실제 연구가 없을 때 Home의 'Selected work'를 **예시 자료 보기/예정된 연구 방식**으로 구분. 실제 데이터가 등록되면 '발행 연구'가 자동으로 우선.
- 이유: 신뢰는 성과를 크게 보이게 하는 것보다 **확정 사실과 기획·예시를 엄격히 나누는 것**에서 시작한다.

### P1. 읽기 크기와 정보 위계

- 현재: 헤더·레이블·보고서 본문 보조 정보·Recruitment 단계 설명에 10~11px 다수. 일부 모바일 본문은 11~13px.
- 단기: 중요한 본문 13~15px, 검색 입력 모바일 16px, 터치 컨트롤 최소 높이 약 44px를 선택적으로 적용. 장식성 대문자 레이블은 일부 작게 유지.
- 큰 개편 시: 단순한 4단 계층(대제목/구획 제목/주 본문/메타데이터) 토큰화. 레이블 글자 간격과 한국어 줄바꿈 폭도 일관 관리.
- 이유: '큰 제목+매우 작은 설명' 대비는 화려할 수 있지만 대학생에게 과업 내용을 읽히는 목적에는 손실.

### P1. 같은 가치를 여러 화면에서 반복하는 구조

- 현재: Home '기업을 이해→가정 검증→설명', About 세 역량, About 4단 경험, Activities 15주 과정이 메시지 측면에서 반복.
- 큰 개편 시: Home은 **정체성과 한 학기 결과**, About은 **왜/누가/무엇을 중요하게 여기는가**, Activities는 **실제 주차별 방법**, Research는 **결과물**이라는 역할로 분리.
- About 4단계는 핵심 문장을 처음부터 보이고 그래픽/상세만 선택적으로 여는 방식 고려.
- 이유: 정보를 감추는 클릭 대신 **중복 설명을 제거**해 길이를 줄이는 편이 덜 피곤하다.

### P1. 메인 히어로의 사진과 모션

- 현재: 건축물·사무실 Unsplash 이미지 3개, 10초 자동 순환, 큰 영문 타이틀.
- 대안: ① 1장 고정형 브랜드 히어로(운영 부담 가장 적음), ② 실제 보고서·차트·가치평가의 과정을 소재로 한 **Research Dossier형 시각 언어**(선호).
- 불필요한 사진 캐러셀 제거 후보. 사용자에게 차트 장식만을 보여 주는 것은 지양; 실제/설명 가능한 근거만 시각화.
- 이유: 감성·몰입은 유지하되, 이 금융 동아리만의 차별성을 확보. 슬라이드를 눌러야 중요한 정보를 얻도록 만들지 않음.

### P2. 각 페이지의 미세 조정

## 4. 두 가지 방향

### A — Editorial Refinement (이번 브랜치 최소 변경 실험)

현재 네이비·화이트·코랄, 사진+브랜드, 그래픽 개성, 필터/모션, CMS를 보존한다. Identity label 추가, 모바일 검색/실제 본문 가독성 강화, Hero 세로 점유율 절제, 샘플 표기 강화, 정보용 비클릭 항목의 오해성 hover 줄이기.

**장점:** 수정 범위가 작고 기존 사용자 승인 및 작업 누적을 훼손하지 않음. **한계:** '금융 연구 전문 단체'보다 '에디토리얼 금융 사이트'라는 인상 자체는 유지.

### B — Research-first Dossier (대대적 개편 후보; 아직 구현 승인 아님)

히어로를 실제 재무 분석 워크플로와 연구 문서 구조에서 가져온 시각적 아이덴티티로 재구성. 큰 키비주얼 대신 **'우리는 누구 / 무엇을 연구 / 어떻게 일하고 / 무엇을 남김'**의 정보형 헤더. Home의 Why·About의 반복되는 가치 소개를 재배치하고 Research를 가장 눈에 띄는 성과 진입점으로 만들기.

**가령 상단 구조**
```text
SFC / 상명대학교 경영학부 기업재무분석 학술동아리
기업을 읽고, 가치를 검증합니다.
공시·사업모델 → 재무분석 → 기업가치평가 → 발표·보고서
[학회 소개] [활동 계획] [연구 라이브러리]
```

**장점:** 정체성이 빠르고 대학 학회만의 공부·연구 특성이 선명. **주의:** 실제 자료가 없는 초기 학회임을 솔직하게 표현해야 하며, 기존 사진형 히어로의 몰입감이 줄 수 있음. **승인 없이 사이트 전체를 이 방향으로 교체하지 않는다.**

## 6. 검증 필요 항목 / 합격 기준

- **첫 인지:** 5초 안에 학회가 어느 대학의 무엇을 연구하는 단체인지 본문을 추가로 열지 않고 설명 가능한가?
- **신입회원 과업:** 모집 상태·모집 대상·시간·지원 방법 및 미확정 사항을 찾을 때 불필요한 페이지 왕복이 없는가?

- **접근성:** 키보드 탭 순서·초점 표시, ESC 메뉴/모달, 스크린리더 레이블, 대비, `prefers-reduced-motion`, hover 없이 모든 필수 정보 열람.
- **상태·모션:** 빠른 필터 교체, 슬라이드 일시정지, 역사 뒤로 가기, 빈 결과·네트워크 실패·연결 지연. 사용자가 액션 이후 제어를 잃지 않아야 함.
- **실서비스:** 노로그인 공개 글 열람과 Studio 인증/RLS, PDF/DOCX 및 지원서 로직은 기능검수(Codex) 단계로 분리; 본 디자인 검수에서 PASS로 추정하지 않는다.
