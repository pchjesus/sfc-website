## 1. 목적과 경계
Readiness는 정식 v3.0~v3.4의 기술적 선행 작업 묶음이며 새 버전 출시를 의미하지 않는다. R0~R8은 보고서 없이 진행할 수 있다. 실제 자료에 의존하는 편집·분류·시각화·학회 정보·발행·인덱싱은 후속으로 남긴다. 사용자 요청으로 실제 개발자/관리자 계정 생성과 운영 DB 변경은 보류. 모든 코드 구현은 별도 브랜치, 모의 데이터, 검증, 소유자 확인, 명시적 병합 승인 순서. 실제 파일/인물/수치/이메일/비밀/미승인 보고서를 공개 브랜치, artifact, 미리보기, 테스트 로그에 넣지 않는다. 외부 API/유료 서비스/새 프로젝트 및 운영 DB·Storage·Auth 변경은 별도 승인. 기존 디자인·7개 탭 고유 모션·사진·About 문구·학교 마크·People/Recruitment 정보 즉시 표시 유지. 필요성이 확인되지 않은 기능과 복잡한 UI는 추가하지 않는다.

## 2. 작업 순서와 수용 기준

### R0 — 기준선·기술 부채 (모든 버전)
- 이미 반영된 문서 기준선을 최신 main에서 재확인. npm test, quality/preview Actions, 기존 82개 브라우저 시나리오를 기준으로 삼고 새로 실행한다. 동일 소스 SHA, 실패 재현, 환경 기록.
- Studio 게시글/구조화 탭의 계정 전환·로그아웃·느린 응답·권한 회수·저장 실패 경로 조사. 이전 계정의 상태/폼/진단/복구 자료가 다른 계정에 표시되지 않도록 우선 수정. 공통 모듈 책임/중복 및 미리보기 생성 방식 확인. P0/P1 결함 우선; 미해결 항목과 재현·수정 범위 명시. 대형 리팩터링 금지.
- 완료: 기준선 재실행 결과, 재현/분류표, 결정 기록, 브랜치 SHA, 위험 및 제외 범위. 문서 최신화는 이번 docs PR에서 선행되지만 R0 기술 검증은 아직 실행 전.

### R1 — 작성 환경 완성 (v3.0 / v3.2 S1·S2 일부)
- 공개 Reader와 Studio가 동일한 안전한 본문·메타·방법·한계·목차 렌더러를 재사용. 미저장 내용/PC·모바일 폭/로컬 PDF의 표시 일치, 외부 미공개 URL 호출 금지. 현재 Reader 동작과 링크 보존.
- 선택 영역에 지원 문법 적용, 실행 취소/다시 실행, 키보드·붙여넣기; 연구/공지/활동 빈 템플릿 및 기존 글 복제(새 draft, 첨부/예약/승인 미승계).
- 수정 이력 및 CAS 충돌 시 서버 최신본과 로컬 작업을 읽기 전용 비교, 복사·수동 병합; 자동 덮어쓰기 금지. 공개 글은 현행 로컬 작업본 정책 유지(영구 분리 스키마는 R4 설계).
- 완료: 동일 fixture의 Reader/미리보기 DOM 및 의미 비교, undo/redo·선택 범위·빈/긴 본문·XSS, 복제/충돌/이력/새로고침 테스트, 공개 데이터 불변.

### R2 — 발행 검수·파일 공개 가드 (v3.0 / v3.2)
- 글 종류별 간결한 검수 대화상자: 제목/요약, 저자/대상, 출처·원문 대조, 승인된 첨부/공개 허가, 미리보기, 즉시/예약 시각. 사람의 확인이지 사실 검증 완료 표시 아님. 본문/첨부/예약 변경 또는 계정 전환 시 체크 무효화, 취소 시 무쓰기. 현재 입력 시간대와 KST/UTC 환산 명시; 과거·잘못된 시각 검사. 예약 첨부 금지 유지.
- 공개 파일 경고: public bucket은 게시물 상태와 별개, draft/preview 비공개 파일 업로드 금지. 업로드/게시 실패 상태 분리, 고아 파일 후보 식별용 구조 설계(삭제 금지).
- 완료: 체크 없이 게시 불가, 변경 후 재확인, 실패/취소/연속 클릭/시각 경계, mock 공개→비공개→예약→휴지통 연계. 실제 파일 공개 보안은 별도 live gate.

### R3 — Research Importer 검수 기능 (v3.0 / RI 0.1~0.3)
- 기업/산업/거시/기타 분석 지침 선택, schema 0.1 호환 및 버전 정책. 원문 위치/단위/기간/출처 누락, 오류·경고·안내 구분. 합성 수치의 산술/단위 일관성 점검은 가능한 범위만; 원문 진위 확인·분석 품질 주장 금지.
- 필드별 적용 확인, 기존 작업 보호, 신규 미저장 draft만 적용. 검토용 JSON 내보내기(로컬, 민감정보 경고), AI review_status 검증 완료 금지. 가져오기 전/적용 직후 네트워크/서버 쓰기 금지, 첫 수동 저장 유지.
- 완료: 정상/누락/잘못된 날짜·단위/악성·과대 JSON, 호환·취소·재가져오기·필드 선택, export/reimport 테스트. 실제 원문 분석 I-08 및 API I-09 NOT RUN.

### R4 — 운영·개발자 도구 및 안전한 기반 (v3.2)
- Release: 배포/빌드 식별값과 실제 SHA 구분; 확인 불가 시 미확인. Diagnostics: 조회 실패 구분·시간·권한 상태, 개인정보 없는 결과 export. 비밀키/서버 전체 로그를 브라우저에 넣지 않음.
- JSON 백업 검사: 스키마/버전, 필수 테이블, 행 타입/참조/중복/누락/크기, 체크섬 검증 지원 및 미디어/Auth 미포함 경고. 모의 복원은 합성 fixture 전용 격리 환경에서만 수행; 외부 JSON이 운영 DB에 쓰이지 않게 한다.
- Test Workspace: 실제 Studio 소스에서 결정적으로 standalone demo 생성, fixture 및 역할 전환·초기화; 네트워크 차단 CSP, 실제 SDK·설정 제외, 브라우저 세션/저장소 분리. public preview 링크는 mock 전용이며 noindex 및 sitemap 제외.
- 운영 데이터 기반 설계: 공개본/작업본과 검수 상태, People/Activities CAS, private staging/media manifest 및 참조 점검, 고아 파일 dry-run, 감사 이벤트, 운영 백업/복원 절차, 개발자/관리자 초대·회수. 필요한 SQL·서버 인터페이스와 격리 테스트 후보까지 작성하되 운영 적용/유료 staging/실제 초대·삭제·복원은 금지. DB 변경 의존 기능은 실제 연결 대신 격리 후보로 명시.
- 완료: mock backup valid/invalid 및 복원 비교, 데이터·권한 음성 테스트, preview 외부 요청 0건, 진단 실패·role 전환, 설계/rollback 및 실제 승인 항목 분리. 사용자 승인 전 실환경 미적용.

### R5 — 설명서와 운영 흐름 검증 (v3.2 / S3)
- 현재 구현된 기능만 설명하는 한국어 Studio 온라인 도움말/원고, 빠른 시작, 탭별 작업/저장/복구/발행/파일/계정/백업/오류. 개발자 부록 및 버전/검증 기준. 화면 캡처는 mock only. 구현 예정 또는 실환경 미검증 기능을 구분.
- R1~R4 통합 workflow: 새 글→import→편집→preview→검수→mock publish→공개 Reader→비공개/예약/복원. 실제 계정·PDF 서버 검증은 보류. 최종 PDF 설명서는 실제 기능·권한·발행 흐름 확정 후.
- 완료: 도움말 링크·내용 일치, 합성 E2E, 기존 82개 회귀. R6~R8 후 도움말과 통합 QA 최종 갱신(RC).

### R6 — Research Library 기술 기반 (v3.1)

- 동일 기업 우선→동일 산업 순의 공개 자료만 추천하는 설명 가능한 순수 로직 및 테스트. 현재 연구가 없거나 적으면 관련 자료 UI를 숨김; 실제 분류·동의어·복수 저자·학기/연도·종목코드 필드와 UI 밀도는 보고서 분포 검토 후 확정. 실제 공개 RLS 우회 금지.
- 완료: 검색·정렬·페이지 정확성, 쿼리 URL 및 기존 링크 호환, 빠른 연속 필터·느린 응답·오류·미공개/예약/삭제 음성 fixture. 필터 과잉 노출 금지.

### R7 — Society Identity 운영 기반 (v3.3)
- 홈페이지/People/Activities/Recruitment의 편집/공개 preview, 필수값·길이·표시 순서·중복 순서/일정 검증, 계획/실적 구분 설계, 상태별 빈 화면 및 로딩/오류/미설정 구분. 현재 공개 정보 즉시 열람과 탭 디자인 유지.

### R8 — Public Reach 기반·최종 RC (v3.4)
- 기존 root canonical/OG, robots.txt와 root sitemap 점검. admin 및 mock preview noindex 유지, sitemap에 실제 공개 URL만, robots로 비밀 보호하지 않음. 사이트 정체성/설명·공유 메타 중 확인된 정보만 개선. 직접 링크/해시 및 기존 query 호환 테스트.
- 보고서별 고정 URL/slug·canonical·OG·sitemap 생성기는 합성 데이터에서 기술 검증만. 미공개/삭제/예약 전 자료를 정적 HTML·빌드 artifact·sitemap에 포함하지 않고 비공개 후 캐시/검색 잔존 위험 고려. 실제 자료·동기화 및 URL 정책 승인 전 공개 배포 금지.
- 접근성: 키보드/탭/초점 복구/모달 Escape/aria/대비/글자 확대/reduced-motion/360px 좁은 화면, 필요 시 axe와 수동 검사. WCAG 2.2 AA 전수 준수 단정 금지.
- 성능: 이미지 크기·lazy loading·PDF 지연·불필요한 JS/요청·레이아웃 이동 점검. lab Lighthouse/브라우저 결과 전후 비교, 기존 모션·사진 유지. 현장 p75 LCP≤2.5s, INP≤200ms, CLS≤0.1은 장기 목표이며 충분한 실제 사용 데이터 전에는 lab만 보고.
- RC: R0~R8 전수 mock/정적/브라우저 검증, Codex 독립 리뷰 P0/P1 해결, 최종 운영 도움말 갱신, 승인된 mock URL 제공, 사용자 확인 이후 main 병합/Pages 실제 접속 확인. 실제 Auth/RLS/Storage/실제 보고서/검색 노출은 NOT RUN으로 분리.

## 3. 순차 구현 및 검수 단위

| 패키지 | 순서 | 범위 | 게이트 |
|---|---|---|---|
| A | R0 → R1 | 기준선 및 편집기 | 저장 안전·Reader parity |
| B | R2 → R3 | 검수 및 Importer | 공개 안전·신규 draft |
| C | R4 | 운영 도구·격리 환경 | 모의 복원·권한·네트워크 차단 |
| D | R5 | 설명서 및 운영 E2E | 실제 기능 설명·mock 발행 |
| E | R6 | Research Library 기반 | 검색/페이지/링크 안정성 |
| F | R7 | Society Identity 기반 | 공개 정보 상태/검증 |
| G | R8 | Public Reach + RC | 접근성/성능/전수 검증 |

각 단계는 앞 단계의 검수된 SHA를 기준으로 시작; 미병합일 경우 dependent branch 명시. 각 PR: 구현/제외/테스트 환경·결과·SHA/알려진 한계/미리보기/rollback. 안전한 mock-only 미리보기 파일의 별도 공개는 소유자 승인 범위 내에서만; 실제 운영 코드·DB와 구분. 기존 82개는 최소 회귀 기준이지 이후 테스트 수 상한이 아니다. R0부터 순차 실행하며 명세와 구현 사이 변경은 기록한다.
