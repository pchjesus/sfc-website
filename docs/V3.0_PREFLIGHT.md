이 문서는 실행 가능한 사전 체크리스트와 자료 분석 양식이다. 현재 실제 보고서 없음. 실제 관리자 계정과 staging 생성, 운영 DB 변경, 파일 업로드, 콘텐츠 발행은 시행하지 않았다. 아래 실제 발행 체크박스는 미실행 사항이며 검증 기록으로 사용한다. 합성 검증 완료 현황은 기준선 문서 참조.

## 1. 첫 보고서 수령 양식 (비공개 채널에서만 작성)

| 항목 | 입력/확인 |
|---|---|
| 원본 파일 | 최종 PDF, 선택적으로 원본 문서/재무모델 |
| 공식 제목/연구 유형 | 미확인 |
| 작성자/연구팀/소속 | 미확인 |
| 원본 작성·제출일/데이터 기준일 | 미확인 |
| 공개 허가 주체·범위·날짜 | 미확인: 전문/요약/차트/사진 각각 |
| 외부 자료 및 저작권 | 미확인 |
| 개인정보/비공개 정보/파일 메타데이터 | 미확인 |
| 내용 검수 담당자 | 미확인 |
| 발행 승인 담당자 및 예정일 | 미확인 |

실제 파일/작성자/허가 기록은 public GitHub 브랜치·PR·Actions artifact에 저장하지 않는다. 미승인 자료는 로컬/승인된 비공개 작업 공간에서만 처리. 표는 실제 자료 수령 후 별도 사본에 작성한다.

## 2. 분석 및 Reader 변환 작업표

- [ ] 원본 보존 및 최종본 버전/파일 크기/해시 확인. PDF 페이지 수/문자 추출/표·차트 판독 가능 여부.
- [ ] 연구 목적, 배경, 핵심 질문, 대상, 연구 유형, 방법, 데이터 출처, 산업/기업/재무/가치평가(해당 시), 결과, 저자 결론, 가정, 한계와 위험.
- [ ] 주장의 근거 수준 및 원본 내부 일관성(단위·기간·기준일·부호·수식/계산). 오류는 별도 검토 의견으로 제출; 승인 없이 저자의 결론 수정 금지.
- [ ] 웹 요약 작성: 제목, 350자 이내 개요, 연구 질문, 핵심 결과, 방법, 가정/한계, 결론·참고자료. 보고서 유형에 맞게 조정하고 분석 방법/한계가 자동 추가되는 Reader에서 중복 방지.
- [ ] 근거 매핑: 각 주요 주장/수치 → 원문 페이지·표/그림 번호·출처·단위/기준일. APA 7 참고자료는 원문에서 확인한 항목만.
- [ ] 공개 허가 및 제3자 이미지/데이터 재사용 조건 확인. 공개용 PDF만 첨부, 20 MiB 제한 초과 시 원본 보존과 승인된 대안 검토. PDF 접근성/텍스트 및 모바일 외부 열기 확인.
- [ ] 실제 보고서 미리보기 및 원문 대비 검수, 학회/소유자 승인. 공개 허가 미확인 시 발행 중단.

| published_at | 웹 발행 시각(원본 작성일과 별도) |
| status / scheduled_at | 승인 상태/발행 정책, 예약 미공개 파일 주의 |

## 5. 실제 Auth/RLS/Storage 검증 게이트 (현재 NOT RUN)

- [ ] 프로젝트 소유자 승인, 격리 staging/local 우선. 실제 프로젝트에 임의로 Auth 사용자/관리자를 생성하지 않음. 비용 발생 변경도 별도 승인.
- [ ] 첫 관리자 실제 계정 활성화(README/CODEX_QA 절차 참고), 이메일 검증, 공개 가입 비활성화 및 recovery redirect 설정 확인. 계정·비밀번호/토큰은 GitHub와 로그에 기록 금지.
- [ ] 역할별 anon/인증된 비관리자/승인 관리자 세션 사용(서비스 역할 키로 우회 금지). 모든 CMS SELECT/INSERT/UPDATE/DELETE, revisions/설정/인물/교육과정/권한 및 Storage 직접 요청을 정책별로 점검. 실제 write-negative 시험은 staging에서, 운영 시험은 별도 승인 및 무해한 데이터/범위로 한정.
- [ ] 관리자 CRUD, 예약/공개/비공개, 실제 파일 렌더, 계정 복구, 권한 해제, 최대 3인 제한은 격리 계정/자료로 확인.
- [ ] 현재 공개 버킷의 파일 직접 URL은 게시물 상태와 무관. 예약 또는 미승인 PDF 업로드 금지. 비공개 파일이 필요한 경우 S0/v3.2 private staging 설계 및 승인 우선.
- [ ] 데이터 정리/삭제/복원은 사전 승인과 백업, staging 범위에 한정. 실패시 운영 발행 중단.
- [ ] 결과 기록: 테스트 ID, 환경, SHA, 날짜, 결과 PASS/FAIL/NOT RUN, 증거 및 제약. 실제 운영 테스트를 mock 결과로 대체하지 않음.
