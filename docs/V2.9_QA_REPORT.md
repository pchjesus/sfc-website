## 2. 실제 DB 읽기 전용 결과

SFC 프로젝트 `nnoicikkennbihjdoivt` (`ap-northeast-2`, PostgreSQL 17), 상태 `ACTIVE_HEALTHY`.

| 운영 현황 | 확인한 값 |
|---|---:|
| Auth 사용자 | 0 |
| superadmin 지정 | 0 |
| CMS 게시물/연구보고서 | 0 |
| CMS 공개/비공개 구성원 | 0 |
| CMS 주차/과정 | 0 |
| CMS 설정 | 2행 (site / recruitment) |
| SFC Storage 객체 | 0 |
| `cms_*` 6개 테이블 | RLS 전부 활성화 |
| Supabase Security Advisor | 경고/오류 0건 |
| Performance Advisor | 사용 기록 없는 인덱스 3건(INFO, 현재 빈 테이블이라 즉시 삭제 불필요) |

**정책/DB 권한 조회 결과**
- `anon`: 게시물/인물/과정/공개 설정 읽기만. CMS INSERT/UPDATE/DELETE 데이터 권한 없음.
- `authenticated`: 관리자 전용 쓰기는 `sfc_private.is_superadmin()` RLS 조건 아래에서 허용. 단순 로그인만으로 관리 가능하지 않도록 설계.
- 게시물 공개 조건: `status='published'`, `deleted_at IS NULL`, `scheduled_at IS NULL OR scheduled_at <= now()`.
- `cms_post_revisions`: `anon` 읽기·쓰기 권한 없음, authenticated는 superadmin일 때만 읽기 가능하고 직접 쓰기 불가.
- 관리자 지정·해제 가드 및 게시글 변경 이력 트리거가 실제 DB에 존재.
- 내부 `sfc_private`의 `SECURITY DEFINER` 함수 3개는 schema 사용·EXECUTE 권한이 제한되며 `search_path` 고정. `is_superadmin()`만 authenticated 실행 가능, anon은 불가.
- 공개 버킷 `sfc-media`: 20MiB 파일 제한, JPEG/PNG/WEBP/PDF/DOCX MIME allowlist. Storage 객체 변경 RLS 역시 authenticated superadmin 조건.
- 참고: 공개 버킷은 **첨부된 빈 지원 양식과 공개 보고서용**. 개인정보가 있는 실제 지원서/이메일/사적인 연구 초안은 절대 업로드하면 안 됨.

**결과 해석 한계:** pg_catalog 정책 확인은 구성 검증이며, 임의 JWT·실제 비인가 계정·스토리지 HTTP upload 시도·Auth 설정 확인의 대체가 아니다. Advisor 결과가 비어 있어도 전체 보안을 보증하는 것은 아니다. 현재 Auth 사용자 0명이라 실제 권한 상승·토큰 탈취·실사용자 복구 테스트는 할 수 없다.
