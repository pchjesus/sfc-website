## 0. 재검토 결론 — 차별화 기준

기존 안은 모든 화면에서 '페이드 + 작은 위로 이동 + 순차 등장'을 반복할 위험이 있었다. v2.8.1은 **화면마다 주연 모션을 다르게** 지정한다. 모든 요소에 동일한 등장 효과를 적용하지 않는다.

| 화면 | 화면 고유의 시각 문법 | 대표 모션 | 보조 움직임 | 의도적으로 정적인 부분 |
|---|---|---|---|---|
| Home | 사진/큰 타이포/편집형 섹션 | **사진 크로스페이드와 슬라이드 본문 교체** | CTA 및 콘텐츠의 짧은 순서 | 슬라이드 외 본문·샘플 고지 |
| About | 분석 단계와 SVG 도식 | **도식 내부 관계 강조(단계별 다른 안무)** | 선택선·설명 전환 | 승인된 3줄 소개의 위치와 텍스트 |
| Research | 정보 목록/필터/Reader | **항목 위치 보존 및 FLIP 재배치** | 선택선·목차 위치 표시 | 검색 입력·DEMO/EQUITY 분류 |
| Activities | 단계 선택/주차 상세 | **수직 펼침·높이 변화** | 선택 범위·문맥 라벨 | 주차 제목·요약·상단 구조 |
| People | 사람/직책/책임 | **편집형 인덱스·구분선 강조** | hover·실제 데이터 교체 | 이름·역할·업무 내용 |
| Recruitment | 모집 상태/지원 행동 | **상태 변경과 CTA 표면의 전환** | FAQ/모달의 열림 | 상태/지원가능 여부/네 절차 설명 |
| Updates | 공지/발행일/기사 | **게시물 행의 구분선·카테고리 선택** | 목록 교체·본문 진입 | 날짜·오류·빈 목록 텍스트 |

**공통 규칙:** 시각 효과는 브랜드 분위기 / 공간적 인과 / 실제 상태 피드백 중 하나를 반드시 가져야 한다. 읽기 위한 텍스트를 숨겨 놓고 기다리게 만들지 않으며, 클릭해야 중요한 정보가 보이는 패턴을 늘리지 않는다.

## 1. 정확한 보존 계약

- **이미지/색/카피:** 기존 Home의 Unsplash 사진 3장과 사진형 히어로, 영문 제목·CTA, navy/white/coral 팔레트, Selected work 샘플 고지. 새 AI 생성 이미지·슬로건·대형 패널/카드 없음.
- **About:** 사용자 승인 3문장은 기존 정확한 `.about-approved-copy .about-line` 3블록으로 유지. 761px 이상 단일 행 3개를 우선, 작은 화면은 각 문장 블록을 유지한 채 내부 줄바꿈. 세 이유 SVG·4단계 Observe/Analyze/Value/Defend 유지.
- **Research:** `DEMO / EQUITY RESEARCH`는 **같은 줄**에서 읽혀야 하고 그 외 타입도 유지. 검색·정렬·산업 필터·list/grid·페이지네이션·deep link·Reader와 게시물 발행 여부 판단 전부 보존.
- **Activities:** **외형·탭·주차 자료·주차별 요약 즉시 노출 유지**. 기존 단계 선택 및 주차 상세만 부드럽게 제어. 학습 계획 구간을 실제 진행률로 재해석하지 않음.
- **People:** 실제 사람과 기획 직책을 혼동하지 않음. `setPeople()`이 렌더하는 역할/이름/업무는 전부 즉시 보임. 인물 공개 시 이전 '계획 조직'과 혼합하지 않음. 미래 회장 사진/인사말은 데이터 등록 전 만들지 않음.
- **Recruitment:** `planned/open/closed` 상태와 링크·모달·파일 유무 연결 보존. 모집 정보 2×2·모집 절차 네 단계를 숨김 없이 표현. 가짜 지원 완료 단계나 진행률 없음.
- **Updates:** 실제 공개 게시물, 발행 날짜, 카테고리·필터, 0건/매칭 없음/접속 실패 구분 및 재시도 보존. `#post`는 Research Reader도 공유하므로 문서 유형에 따라 제목·목차만 다르게.
- **전역:** `main` 릴리스에 포함된 하단 상명대 로고는 정적; 기존 7탭 해시/뒤로가기/스크롤 위치, CMS, Studio, Auth·RLS·Storage·SQL 수정 없음.

## 2. 공통 시스템: 모션 트리거·시간·중단

| 이벤트·역할 | 시간 목표(초안) | 기술 방식 | 접근성·동기화 |
|---|---:|---|---|
| 상위 탭 변경 | 180–260ms | **전체 페이지 .35→1 페이드 제거**. 탭 활성선만 짧게 이동, 화면은 즉시 보이고 화면별 주연에만 효과 | 뒤로가기·재진입에서 초기화/중복 실행 금지 |
| 브랜드 첫 진입 | 320–460ms | 최초 방문 화면에만 opacity·최대 6px의 정착 효과 | 텍스트 시작 opacity ≥ .65, DOM 즉시 읽기 가능 |
| 선택 탭·선 | 160–220ms | translate/width를 실제 선택 요소 위치로 보간 | `aria-selected`, `aria-pressed` 먼저 갱신 |
| 필터·정렬 재배치 | 220–320ms | keyed FLIP/translate. 불연속 목록은 위치 이동 대신 짧은 content fade | 내용·카운트 즉시 갱신; 중단 시 마지막 상태 |
| 확장·접기 | 230–300ms | 실제 내용 높이 기반. hidden/inert/ARIA 동기화 | 긴 본문 잘림 없음 |
| 모달 | 240–300ms | opacity + Y ≤6px, native dialog 유지 | ESC·초점 트랩·복귀·스크린리더 |
| Hover·Focus | 140–190ms | 색/선/작은 화살표. 키보드 focus-visible은 **즉시** | 터치에서 hover 의존 금지 |
| 오류·빈 상태·실제 모집 상태 | **즉시 (0ms)** | 상태 우선. 배경색만 선택적으로 120–180ms | 진짜 데이터 전환만 표시 |

- 장면당 대표 모션은 **하나**; 보조는 최대 둘. 시각적 스태거 총 지연 **140ms** 이하. 스크롤할 때 나타난 콘텐츠는 동일 방문 중 다시 숨겼다가 보여주지 않는다.
- 사진 진입 시 해상도를 낮추는 Blur-up이나 별도 parallax/zoom은 사용하지 않는다. 기존 Home 이미지의 10초 앰비언트 확대·시간바는 그대로 두되 **실제 슬라이더 상태와 연계**한다.
- `prefers-reduced-motion: reduce`는 비필수 모션·자동 이미지 이동을 중단. JS 중단/취소에 따른 마지막 DOM·ARIA·클릭 상태를 항상 보존한다.
- 불필요한 `will-change` 상시 설정과 큰 `filter: blur()`, 대형 `box-shadow`, 대규모 DOM 복제 금지. motion 중단·hidden 탭 전환 시 WAAPI animation/ghost 노드 회수.
- 네비게이션 인트로와 섹션 개별 리빌을 **이중 실행하지 않는다**. 페이지 상단 제목이 이미 보인 경우 재방문에 효과 중복 적용 금지.
- 뒤로가기/직접 # 링크/스크롤 복원은 사용자의 위치를 우선. 새 페이지에서 자동 스크롤시키는 연출을 만들지 않는다.
- 처음 도착하는 **실제 데이터**와 **처음 등장하는 정적 요소**의 시간축을 분리. CMS 완료 상태가 인트로 재생을 강제하지 않는다.

## 3. 탭별 타임라인과 요소별 사양

### 01 Home — Photographic Editorial

**기존 요소:** `#hero`, 3개의 `.hero-photo`, `#heroCopy`, `#heroHeading`, `#heroDescription`, `#heroButton`, `.hero-controls`, `#heroProgress`, `.home-value-compact`, `.featured-work`, `#homeWorks`, `.process-points`, `.join-strip`.

**대표 모션: 슬라이더 사진·현재 제목의 동기화.**

1. 첫 진입(시퀀스): 사진과 첫 본문 즉시 존재 → `#heroHeading` 0–420ms opacity .7→1/6px 정착 → 설명은 시작 +70ms, 280ms fade-only → CTA는 시작 +115ms, 250ms. 01/02/03 컨트롤은 **최초 프레임부터 보임**.
2. 사진을 바꿀 때: 현재 `js/site.js:setSlide()`은 `#heroCopy` 전체를 약 **720ms** 다시 페이드한다. 이것을 **슬라이드 본문 교체에 한정된 200–280ms 정착**으로 바꾸고 자동/수동 모두 같은 선택 상태를 정확히 반영. 01/02/03을 클릭했을 때 페이지 전체·다른 섹션까지 재등장하지 않음.
3. 기존 10초 자동재생 + `#heroProgress`는 **실제 타이머**를 나타내도록 유지. 포커스/마우스/비가시 상태·저감모션에서 일시정지 조건 점검. 사진 자체의 큰 확대·두 번째 시차 효과 추가 없음.
4. WHY SFC: 문장 애니메이션보다 섹션 진입 시 왼쪽 **짧은 제목/강조 단어의 대비 전환**(280ms). 본문은 정적. 빈 여백에 새 패널을 넣지 않음.
5. Selected work: **사진 프레임/설명 2열**을 하나의 내용으로 취급. 화면 진입 시 하단 테두리 또는 설명 영역에 220ms accent line. 실제 샘플 표시는 정적. Hover/focus 화살표 2–3px 이동.
6. Program: 3개의 과정 행 **왼쪽 번호와 구분선**이 40ms 차로 160–240ms 강조. 모든 행의 제목/주차는 즉시 보임. 실제 학습 진행을 시뮬레이션하는 막대 없음.
7. Join: CTA만 180ms 반응. 밴드가 빈 화면에서 슬라이드 인하는 효과 없음.

**상황별:** Home→다른 탭→Home 복귀 시 풀 인트로 재생 금지. 사진 자동재생은 원래 중단·재개 정책 준수. 첫 사용자 조작 시 대기 없이 즉시 반응.

### 02 About — Analytical Storytelling

**기존 요소:** `.about-photo-panel h2`, `.about-approved-copy .about-line`×3, `.about-reason`×3(SVG), `.experience-selector`, `#experiencePanel`, `[data-experience-visual="0..3"]`, `#experienceHeading/Copy/Outcome/Counter/Next`.

**대표 모션: 단계별 SVG의 서로 다른 논리적 변화.**

1. 소개 사진과 3줄: 사진은 보이는 상태. 제목은 약 320ms opacity 정착. 세 문장은 **텍스트 전체를 숨기지 않고** 45ms 간격, 각 줄 260ms 이하의 밝기/강조 전환. 정확한 3문장과 줄바꿈, 본문 폭, CMS 기본값 호환 불변.
2. 역량 그래픽 3개: 카드의 등장 효과보다 **SVG 한 요소씩 짧게 강조**. 01 재무 분석은 그래프의 한 지점을 강조, 02 기업가치평가는 두 경로의 차이(실측 결과로 오인 금지), 03 리포트는 문서 테두리/내용의 대비 변화. 각 스크롤 노출 1회, 180–260ms.
3. 선택 탭: active underline 190ms, `aria-selected` 먼저 확정. 설명/패널은 180–220ms의 짧은 교체.
4. Observe: 산업/기업/고객 **연결선의 stroke-dashoffset**을 250–330ms 짧게 드러냄. 연결 구조의 의미.
5. Analyze: 기존 막대 높이는 고정. **막대 그룹 대비가 0.7→1**, 추세선 opacity 강조 260ms. 차트 데이터 변화처럼 보이지 않도록.
6. Value: 가치평가 비교 곡선과 주황색 가정 프레임을 순서대로 180ms+160ms 강조. 곡선을 새 값까지 '성장'시키지 않음.
7. Defend: 기존 겹친 보고서 용지의 **전면 페이지 테두리/내용**이 240ms 정착. 종이가 화면 위로 날아다니는 모션 없음.
8. 빠른 탭 전환/방향키/NEXT STEP: `js/about-experience.js:select()`의 기존 설명 애니메이션 cancel을 확대해 SVG 내부 애니메이션도 취소. **마지막으로 선택한 단계만** 표시하고 포커스/aria 관계 유지.

**피함:** 텍스트 스크램블·시차·도식 전체 과장 확대·글자를 지연 공개하는 마스크.

### 03 Research + Reader — Spatial Reorganization

**기존 요소:** 동적 `#researchWorkbench`, `#archiveSearch`, `#archiveSectors`, `#archiveSort`, `#archiveListButton/#archiveGridButton`, `#archiveResults .archive-report`, `#archiveCount`, `#archivePager`; `#post` Reader, `#readerToc`, PDF dialog.

**대표 모션: 동일 보고서 객체가 위치·배치만 바꾸는 공간 연속성.**

1. 제목/도구줄은 **애니메이션 거의 없음(0–180ms)**. 사용자는 즉시 검색할 수 있어야 함.
2. 첫 결과 목록은 이미 읽을 수 있는 opacity .8에서 시작, **첫 4개에만 25–35ms 지연으로 180ms 선/미세 위치 정착**. 목록이 0건이면 효과 없음.
3. 검색 220ms debounce, `requestVersion`과 `aria-busy` 유지. 이미 있던 보고서: keyed FLIP 240–300ms; 새 보고서: 정적에 가까운 140ms fade; 삭제된 카드 ghost는 스크린리더·포커스 비활성. 결과 정렬·가로폭 이동 시 흔들림·중복 카드 금지.
4. list/grid 전환은 동일한 `data-motion-key`를 보존하고 좌표만 300ms 내 이동. 기능적으로 1→N, N→1, 0건↔N건 처리. `#archiveCount`와 페이지 표시는 애니메이션보다 먼저 정확히 바뀜.
5. `DEMO / EQUITY RESEARCH`, DEMO 날짜, 공식 발행 여부는 **0ms 즉시 노출**. 샘플과 정식 보고서가 동일한 장식 효과로 섞여 보이지 않게 상태 문구 유지.
6. Reader 이동: 목록과 상세를 억지로 연결하는 확대 대신 **헤드라인과 위치 연결**—상세 진입 시 상단 제목 최대 220ms 대비 정착, 본문은 바로 읽을 수 있게. 목차 현재 항목 underline/left border 150ms, 독서 진행선은 실제 `scrollY/(scrollHeight-innerHeight)`와 연결. 문서 길이가 변할 때 재측정.
7. PDF dialog는 원본 `showModal()`·ESC·초점 복귀를 유지하면서 작은 260ms fade/Y 5px. 네트워크 대기→오류까지 '성공' 모션 금지.

**특별 검수:** 빠른 검색·정렬을 반복할 때 이전 결과가 나중에 늦게 뜨지 않는지, 필터에서 카운트/URL query 보존, Reader에서 뒤로가기 시 원래 목록 스크롤 위치 복원.

### 04 Activities — Progressive Disclosure (구조 그대로)

**기존 요소:** `#journeyContext`, `#journeyCurrent`, `#journeyDescription`, `#journeyRange`, `#journeyProgress`, `#scheduleTabs`, `#scheduleList`, `.session` 및 `.cms-session`.

**대표 모션: 주차 내용이 펼쳐지는 수직 공간 변화.**

1. 상단 구조·전체 과정/기초교육/기업분석 실습/최종 연구 탭·15주 제목/요약 **원본 유지**. 새로운 지표·카드·스크롤 링크 없음.
2. 단계 전환은 선택선 180–220ms. `journeyContext`의 라벨/설명은 **Y 이동 없는 180ms 대비 정착**, 실제 내용은 즉시 교체.
3. `journeyProgress`는 선택 범위 구분선임을 유지. 220ms 길이 전환은 허용하지만 '이미 78% 수업 완료' 같은 표현 추가 금지.
4. 기존 `filterRows` 기반 **실제 행 높이+opacity 260–310ms**, 각 row DOM과 펼침 상태 보존. all→foundation→research→all 연속 실행 및 닫히는 행에 포커스가 있을 때의 포커스 이탈 검증.
5. 아코디언 `aria-expanded`/inert/hidden를 우선 갱신하고 상세만 240–290ms 확장. 제목·요약을 숨기거나 카드 전체가 흔들리는 동작 없음.
6. 스크롤 강제 이동/전체 행 slide-in/진행률 count-up은 **배제**.

### 05 People — Editorial Index

**기존 요소:** `.people-editorial-lead`, `#peopleGraph`, `#roleList .team-node`, `.team-node-index`, `.team-node-name`, `.team-node-role`, `.team-node-description`, `#peopleDisclaimer`, `.people-next-link`, `setPeople()`.

**대표 모션: 정보의 계층을 설명하는 번호/구분선 강조, 인물 카드 본문은 정적.**

1. 제목·`Behind the research.`는 약 250ms 간단 fade. 핵심 인물 카드(기획 역할/실제 구성원)는 **처음부터 이름·직책·업무가 읽히는 상태**, 카드 자체를 3개씩 순차 slide-in하지 않는다.
2. 화면에 인물 카드가 보일 때 `01 / ORGANIZATION` 같은 **작은 인덱스/위쪽 얇은 경계선만** 170–220ms 강조. 사람에 시선이 모이도록, 여러 카드가 동시에 뜨는 역동적 느낌은 피함.
3. Hover/focus: 카드 배경색/경계 160ms, 화살표가 있는 Recruitment 동선만 2px 이동. 실제 내용 없는 카드가 클릭 가능한 것처럼 변하지 않도록 pointer cursor/transform 금지.
4. `setPeople(records)`이 기획 역할에서 실제 구성원으로 전환될 때는 **교체 후 최종 정보 즉시 제공**, 처음 나타난 이름에만 180ms fade 가능. `#peopleDisclaimer`은 planned/live와 함께 즉시 정확히 변경.
5. 현재 CMS 실제 인물은 `setPeople` 경로에서 텍스트 중심. **실제 사진 렌더 경로는 현 v2.8에서 추가하지 않는다.** 회장 사진/인사말 등 신규 데이터 스키마/파일 처리 별도 작업.

### 06 Recruitment — State-driven Interaction

**기존 요소:** `#recruitStatus`, `.recruit-fact-grid`, `#recruitActionCard[data-state]`, `#applicationTrigger`, `#recruitmentProcess`, `#faqList`, `#applicationDialog`.

**대표 모션: '지금 할 수 있는 행동'이 실제 모집 상태와 함께 바뀌는 표면 전환.**

1. planned/open/closed 상태·기한·지원 가능 여부·CTA 레이블/동작/실파일 유무는 **0ms 동기적 갱신**. 표현만 이후 150–180ms 배경·테두리·강조색 전환.
2. 최초 진입: 2×2 정보는 내용 노출 유지, **각 셀의 구분선만** 0–75ms 간격 180ms 강조. 과한 카드 비행/숫자 count-up 없음.
3. 모집 네 단계는 모두 정적 텍스트. 번호 아래 연결선이 있다면 처음 200ms만 은은하게 밝혀 순서 표시하되 지원자가 통과한 단계처럼 색을 누적하지 않음.
4. FAQ는 240–290ms 실제 높이 기반 확장/축소. 중간에 반복 클릭하면 최종 열린 항목만 남음.
5. PDF/DOCX native dialog: 250ms fade+Y 5px; ESC/밖 클릭/초점 복귀 보존. 실제 파일 없으면 오류 또는 안내를 즉시 보여주고 다운로드 버튼을 표시하지 않음.
6. planned 상태의 안내 스트립은 작은 강조, open 상태의 네이비 CTA는 기존 강한 대비를 그대로 유지.

### 07 Updates + Reader — Publication Flow

**기존 요소:** `.updates-section-heading`, `#updatesFilters`, `#updatesList`, `.cms-card`, `.cms-empty-state`, `#post .cms-post-head`.

**대표 모션: '새 소식/발행 글'을 차분하게 훑는 편집형 목록 리듬.**

1. `LATEST NEWS`와 최신순 표시로 목록 상단의 시각적 기준을 잡고, **행 사이 얇은 구분선/hover 강조**를 약 160–200ms로 적용. 각 게시글 전체를 아래에서 연속해서 띄우지 않음.
2. 공지/활동/리서치 필터의 선택선은 170–200ms. 새 결과가 나오면 기존 `motion.reconcile`로 **정보 교체/위치 변화 220–280ms**. 날짜/제목/카테고리는 동작 시작에 즉시 표시.
3. 데이터 로딩: 실제 DB 응답 전 `게시글을 불러오는 중입니다.` 표시(허위 스켈레톤 금지). 성공→목록, 0건→NO POSTS YET, 필터 0건→NO MATCHES, 네트워크 오류→CONNECTION UNAVAILABLE+재시도. 이 상태 메시지들은 0ms로.
4. 새 게시물 첫 로드의 소규모 리스트 정착은 최대 첫 3개, 25–30ms 간격, 효과 140–180ms. **이후 카테고리 전환에는 리빌 반복 금지**.
5. 공지/활동 Reader에서는 제목 220ms opacity 강조, 본문 정적. Research 리포트와 같은 `#post`를 사용하는 경우 Research Reader 목차/진행선 로직만 해당 문서에 적용. 뒤로가기는 출발한 목록으로.
6. 오류 재시도 버튼은 실제 네트워크 재요청 중 중복 호출만 막고 실패 시 다시 활성화; 완료를 장식적 체크로 가장하지 않음.

### 별도 개발 브랜치

3. Home 슬라이더/첫 화면 → About SVG 4단계 → Research 목록/Reader → Activities 범위/상세 → People 인덱스 → Recruitment 상태/모달 → Updates 목록/본문 순서로 구현.

### 개발 중 체크 (UI 검수, Codex 검증 **이전**)
- 1440/1024/768/390/360px + 200% 확대: first visit / 재방문 / 반대 방향 클릭 / Page Back / History / 수동 슬라이드 연타 / 메뉴 열림 / 검색 입력 중 / 목록 0건 / 실제 및 시연 데이터 / planned·open·closed / PDF 다이얼로그.
- 두 화면 타입 비교: 기존 v2.7과 개선 v2.8의 **실제 동작 녹화 또는 캡처**(단순 HTML 목업 금지), 메인 화면/첫 애니메이션 이후/인터랙션 도중/종료 결과의 상태를 나눠 캡처.
- 정적·사용성 항목 별도 기록: PASS/FAIL/NOT RUN. 스크린샷은 애니메이션 시간감각을 증명하지 못하므로 필요시 2–3초 영상.
- `prefers-reduced-motion` ON/OFF, 키보드 Tab/화살표/Home/End/Escape, 포커스 가림 여부, screen reader 상태 텍스트, CPU throttling/지연 네트워크, 스크롤 정지/동시 클릭/리다이렉트 중 메모리 정리.
- 발견한 문제는 모션 브랜치에서 고치되, 기존 v2.7 정보 구조·편집·CMS 로직에 영향을 주면 범위/원인 별도 보고.
