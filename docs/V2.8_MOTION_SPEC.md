## A. 화면 목적 및 고정된 보존 범위

- Home: 첫인상과 학회 내용 안내. **히어로 사진 3장/슬라이드 그대로**, 기존 슬로건, Selected work 실제/샘플 처리, Program/Recruitment 동선 유지.
- About: 학회 정체성·실제 계획을 읽고 연구 과정 이해. 사진, 그래픽 3개, Observe/Analyze/Value/Defend 4단계, 승인한 **세 줄 소개 문구 그대로**.
- Research: 보고서 발견/비교/열람. `DEMO / EQUITY RESEARCH` 라벨, 검색·필터·정렬·list/grid·페이징, 실제/예시 구분, Reader 링크 유지.
- Activities: **구조 변경 금지**. 15주 커리큘럼·과정 탭·주차별 요약·아코디언·단계 맥락 표시, CMS 세션 교체까지 유지.
- People: 역할/실제 인물·담당 업무 즉시 노출. 중앙 장식 패널 재도입 금지. 회장 사진/인사말은 실제 콘텐츠 등록 이후의 별도 작업.
- Recruitment: 2×2 모집 정보, planned/open/closed 상태, 네 단계 절차 모두 바로 노출, FAQ, 실제 PDF/DOCX만 제공. 모집 상태를 허위 진행률로 표현하지 말 것.
- Updates: 실제 게시물 목록·필터, 0건/필터 0건/오류 구분, 링크/발행일, 독자적인 기사 Reader.
- 공통: 기존 네이비·화이트·코랄·사진, 예시 자료 명시, 로컬 상명대 심볼의 **푸터 배치**, CMS/Studio/SQL/인증/RLS 변경 금지.

## B. 모션 시스템: 단일 원칙이 아니라 역할별 레퍼토리

| 모션 종류 | 트리거 | 목적 | 설계 시작값 | 쓰지 않을 곳 |
|---|---|---|---|---|
| Editorial reveal / 약한 페이드 | 처음 화면에 들어온 고정 섹션 | 내용 위계와 리듬 | 320–480ms, opacity .65→1 / Y 0–8px | 필수 상태, 오류, 검색 결과 업데이트 |
| Image reveal / 사진 정착 | Home/상단 About 사진 최초 진입 | 사진과 타이포 관계 유지 | 사진 자체는 즉시 표시, 위에 작은 마스크/대비 전환만 350–500ms | 전면 흐림·강한 줌·사진 교체 |
| Emphasis line / 선 강조 | 실제 선택 상태 변화 | 탭/필터 결과 연결 | 160–240ms, transform | 진행률이나 완료 실적으로 오인될 곳 |
| Context swap / 맥락 교체 | About 단계, Activities 선택 | 이전 내용과 다음 내용의 연속성 | 180–300ms, opacity+최대 6px | 긴 내용의 읽기를 방해하는 큰 이동 |
| List reflow / 공간 연결 | 검색·정렬·필터·그리드 | 어느 항목이 이동했는지 이해 | 220–350ms, 위치 transform; 중단 가능 | 키 입력 때 매번 모든 결과 재등장 |
| Disclosure / 펼침 | Activities 주차·Recruitment FAQ | 추가 설명 유무 명료화 | 220–300ms, 실제 높이와 aria-expanded 동기 | 핵심 정보 기본 가림 |
| Ambient motion / 배경 변화 | Home 실제 슬라이드 시계 | 브랜드 분위기 | **기존 3장/진행 막대와 사진 전환 유지** | 다른 모든 탭 배경 |
| Immediate state / 상태 표시 | 데이터 로딩·완료·오류, 모집 상태 | 정확한 행동 안내 | **상태 텍스트 즉시**, 애니메이션 0–150ms 이하 | fake progress / 잦은 shimmer |

- 움직임 방향: 일반 텍스트는 아래에서 4–8px 상승 또는 opacity-only, 목록 교체는 FLIP, 메뉴/모달만 분명한 계층 이동. Blur-in, letter scramble, typewriter, parallax, 과장된 bounce/zoom, 숫자 count-up은 제외.
- 시간: 화면 전환 240–360ms; 주요 입장 320–480ms; 상호작용 160–300ms; 스태거 35–65ms, 누적 지연 160ms 이하. 현행 520ms 페이지 진입 + 780/950ms 리빌이 겹쳐 과하게 느껴질 수 있으므로 **합산 시차 최소화**.
- 한 섹션에서 동시에 움직이는 대상은 주요 1개+보조 1~2개까지만. 스크롤하며 여러 패널이 동시에 날아오는 연출 금지.
- 최초 방문 1회 / 다시 탭 클릭 / 스크롤 재진입 / CMS 교체 상황을 구분. 본문은 모션 종료를 기다리지 않고 읽고 클릭할 수 있어야 한다.
- `prefers-reduced-motion: reduce`: 입장 위치 이동·줌·슬라이드 확대·불필요한 연출 제거. 선택·완료·오류 상태와 모든 콘텐츠는 동일하게 제공.

## C. 각 탭: 실제 DOM 요소와 구체적 연출

### 01 Home — 사진과 제목이 주인공

**실제 요소:** `#hero`, `.hero-photo` 3장, `#heroHeading`, `#heroDescription`, `#heroButton`, `.hero-controls` 01/02/03, `#heroProgress`, `.home-value-compact`, `.featured-work`, `#homeWorks` / `#homeLiveResearch`, `#homeUpdates`, `.process-points`, `.join-strip`.

1. 첫 방문: 사진은 즉시 표시. 영문 메인 제목은 현행 두 줄 위치에서 **opacity .6→1 + Y 6px 420ms**, 보조 문구는 약 70ms 뒤 **opacity 320ms**, `DISCOVER SFC`는 그다음 약 50ms 뒤 **opacity + Y 4px 300ms**. 문장 생성·한 글자씩 입력 없음.
2. 슬라이드: 기존 자동/수동, 이미지 페이드, 시간 막대를 유지. 사진 위 텍스트가 슬라이드마다 다시 번쩍이거나 전체 페이지가 재등장하지 않게 함. 마우스·키보드 사용자가 01/02/03을 조작할 때의 일시정지/재시작, 다른 탭 이동 및 페이지 비활성 시의 자동재생 동작 점검.
3. WHY SFC: 짧은 소개는 섹션 진입 시 **fade only 360ms**. 세 값을 다시 등장시키는 새 패널·장식 금지.
4. Selected work: 사진은 그대로, 사진↔설명 본체를 동시에 소규모 fade 420ms. 보고서 카드/링크 hover는 테두리/화살표 X 2–3px 180ms. `DEMO` 레이블은 즉시 표시.
5. Program의 `Foundation / Case Studies / Final Research`: 세 행은 **선/색 강조 35–45ms 스태거**만 주고 숨기지 않음. 실제 수업 진행 퍼센트처럼 길이 움직이지 않음.
6. Join: 모집 동선은 즉시 접근 가능. 밴드 진입시 opacity-only 300ms, CTA 화살표 미세 이동.

**피함:** 전면 페이지 스크롤 패럴랙스, 헤드라인 글자 스크램블, 새 비주얼 그래픽.

### 02 About — 학회 소개 3줄과 도식 연결

**실제 요소:** `.about-photo-panel`(사진), `.about-approved-copy .about-line` 정확히 세 줄, `.about-reason` 3개(내부 SVG), `.experience-selector` 4개의 `role=tab`, `#experiencePanel`, SVG `[data-experience-visual]` 0–3, `#experienceHeading/Copy/Outcome/Counter/Next`.

1. 사진 상단: 사진은 항상 보이고, `h2`는 380ms 약한 페이드. **승인된 소개문구 세 줄은 순차 opacity-only 260–320ms, 간격 45–55ms**. DOM·줄바꿈은 처음부터 존재. PC 물리적 3줄, 모바일 문장 블록 보존(추가 soft-wrap만 허용).
2. 세 연구 역량 SVG: 스크롤 첫 노출 때 카드/텍스트를 40ms 간격으로 서서히 등장; 카드마다 **실제 SVG 요소 1개만** 미세 선 강조 또는 opacity 변환. 가짜 차트 숫자나 값 상승 금지.
3. Observe→Analyze→Value→Defend: 탭 선택선 **180–240ms** 이동, `aria-selected` 즉시 확정. 헤드라인/설명은 **180–260ms fade-through + Y 4px 이하**. 네 도식별로 서로 다른 가벼운 세부 움직임:
   - Observe: 산업–기업–고객 3칸 연결선이 짧게 강조되어 관계를 보여줌.
   - Analyze: 기존 막대·추세선의 투명도 변화. **수치 증가/성장 실적을 암시하는 높이 애니메이션 금지**.
   - Value: 2개 비교 경로와 민감도 사각 프레임을 순서대로 표시(숫자 성과처럼 보이지 않음).
   - Defend: 기존 종이/보고서 그래픽의 소규모 레이어 강조, 큰 확대/카드 뒤집기 금지.
4. `NEXT STEP` 버튼 클릭 및 방향키 이동은 기존 탭 상태를 그대로 사용. 빠르게 반대 방향으로 눌렀을 때 이전 애니메이션 취소 후 최신 단계만 표시. Tab·Arrow·Home·End·focus 유지.
5. 카피를 마스킹해 읽기 막는 1초 reveal은 쓰지 않음. 필요하면 배경 사진의 짧은 진입 연출로만 제한.

### 03 Research (+ Reader) — 탐색이 가장 빨라야 하는 화면

**실제 요소:** `#researchWorkbench` 동적 생성 `.archive-intro`/`#archiveMode`, `#archiveSearch`/`#archiveReset`, `#archiveSectors`/`#archiveSort`, `#archiveListButton`/`#archiveGridButton`, `#archiveResults`/`.archive-report`, `#archiveCount`, `#archivePager`; 공개 원문 `#post`/Reader 목차 `#readerToc`와 본문·첨부·읽기 위치.

1. 탭 진입: 페이지 제목 300ms 페이드, 검색창·도구줄 0–80ms 차이로 250ms 등장. **검색 입력은 즉시 가능**.
2. 최초 결과 목록: 앞쪽 4–6개에만 **opacity .72→1, Y 4px, 220–300ms**, 각 30–35ms 차이(상한 130ms). 보이는 카드에만 적용.
3. 검색: 기존 220ms debounce 유지; 입력 결과가 바뀌면 기존 keyed `SFC_MOTION.reconcile` 기반 **위치 변화 220–320ms**. 검색할 때마다 카드 전부 재등장하지 않음. 이전 요청이 늦게 도착하면 버전 가드(현재 `requestVersion`)가 오래된 목록 표시를 방지해야 함.
4. 산업 탭·정렬·list/grid: 선택선 180ms, 카드 재배치 FLIP 약 300ms. 잦은 토글은 이전 animation cancel, 겹치는 shadow clone 정리. 페이징 다음/이전은 페이지 번호·컨텐츠 즉시 동기화.
5. `DEMO / EQUITY RESEARCH` 및 날짜·기업 라벨은 **처음 프레임부터 가독**. 예시/공개 구분을 반짝임·색만으로 표시하지 않음.
6. Reader/기사: 목록 카드에서 상세로 이동 시 대형 shared-element 확대 대신 **최상단 보고서 제목 300ms 등장**, 본문 즉시 표시. 목차 항목은 활성 구역에 따라 선/타이포 강조 140–180ms; 스크롤은 기존 사용자 제어 유지. 상단 실제 **스크롤 위치 진행 바**만 데이터(문서 스크롤 위치)와 연결. 실험/학습 완료율·연구 진척도로 오인시키지 않음.
7. PDF dialog: 현재 네이티브 dialog + 단축키 Escape/초점 복귀 유지, 투명도와 Y 6px 260–320ms. 비동기 프레임 로딩은 실제 상태 텍스트 유지.

**금지:** 검색 결과 전용 typewriter, 차트 장식, 의미 없는 infinite scroll, 요청 대기 중 가짜 percentage.

### 04 Activities — 확정된 정보 구조를 그대로 유지

**실제 요소:** `#journeyContext` 제목/설명, `#journeyRange`, `#journeyProgress`, `#scheduleTabs`, `#scheduleList` 15주 계획·CMS 실제 세션, `.session` / `.cms-session` 펼침.

1. HTML·주차 텍스트·정보 밀도·탭 종류를 **전혀 교체하지 않음**. 상단 타이틀은 기존 약한 페이드만 280ms.
2. 단계 선택: 현재 단일 선택 상태와 active underline을 그대로 이용, 밑줄 이동 **180–230ms**, 설명 교체 **200ms fade**. `#journeyProgress`는 *선택한 주차 구간의 위치/범위*를 표현하는 보조 시각 요소이지 완료율이 아님. 새로운 진행 퍼센트나 숫자 카운트 금지.
3. 주차 목록 필터: 기존 `filterRows`를 유지하되 높이·opacity 정리는 260–330ms에서 비교. 빠른 all→foundation→research→all 반복 때 항목 인스턴스·펼침 상태 보존.
4. 주차 클릭: 기존 제목·요약은 보존, 상세만 230–300ms 높이 전환. `aria-expanded`/inert/숨김 정확히 동기화. 긴 실제 세션 설명은 높이 잘림/스크롤 튐 여부 검사.
5. 필터만 변경했는데 페이지가 자동으로 맨 위/아래로 이동하는 새 동작은 추가하지 않음.

### 05 People — 누구인지 즉시 보이고 이후 확장 가능

**실제 요소:** `.people-editorial-lead`, `#peopleGraph`, `#roleList .team-node`(계획/공개 구성원), `#peopleDisclaimer`, `.people-next-link`; CMS `SFC_PEOPLE_RECRUITMENT.setPeople` 호출.

1. 제목·소개는 한 번만 300ms fade. 인물/역할 카드는 화면에 들어왔을 때 **opacity .72→1 + Y 4px, 320ms**, 40–55ms 간격(상한 150ms)으로 등장. 이름·역할·업무는 DOM에 이미 존재하고 키보드로 즉시 접근 가능.
2. 카드 hover/focus: border/바탕색 170–200ms, 불필요한 상승·회전·3D 확대 없음. 비활성 카드처럼 보이지 않도록 포커스 대비.
3. CMS 실제 구성원으로 교체될 경우: 가상 직책과 실제 운영진을 섞지 말고 **이미지가 없어도 프로필이 정상 렌더**. 재호출 때 새 카드만 애니메이션.
4. 미래 회장 사진/회장의 말: 현재 새 내용·가상 초상 추가 **안 함**. 추후 사진이 등록되면 이미지의 짧은 fade와 인사말 정적 등장만 별도 설계.

### 06 Recruitment — 상태와 CTA를 행동 우선으로

**실제 요소:** `#recruitStatus` planned/open/closed, `.recruit-fact-grid .recruit-fact` 4개, `#recruitActionCard`, `#applicationTrigger`, `#recruitmentProcess .process-step` 4단계, `#faqList .faq`, `#applicationDialog`.

1. 모집 상태·현재 가능한 CTA **즉시 표시**, 별도 등장 대기 없음. 배경은 planned에서 안내 스트립, open에서 기존 네이비 강조, closed는 공개 Research로 이동하는 현재 계약 유지.
2. 최초 진입: 2×2 모집 정보 **opacity-only 280–350ms**(차이 최대 50ms). 네 개의 선발 절차는 가벼운 25–35ms stagger, 모두 읽히는 상태 유지. 절차 연결선은 있다면 처음 250ms 동안 강조만; **내가 몇 단계 통과했는지 표현하지 않음**.
3. 상태 변경: 수업/모집 일정에 따라 planned→open/closed 시 CTA 레이블, 다운로드 가능 여부, 색과 실제 클릭 행동 **동기적으로 먼저 반영**, 배경색은 180ms 전환 정도. 강조 버튼이 한순간 잘못된 동작을 하지 않게 테스트.
4. FAQ: 기존 내용 숨김은 FAQ 범위에 한정, 펼침/접힘 240–300ms. 내용 누락·빠른 중복 클릭/키보드 포커스 검사.
5. PDF/DOCX 팝업: 네이티브 dialog·focus trap·ESC·backdrop 닫기·초점 복귀 보존; 250–320ms 작은 fade+Y. 실제 다운로드/문서 읽기가 연출보다 우선.

### 07 Updates (+ 공지 Reader) — 속도·상태·읽기

**실제 요소:** `.updates-section-heading` 최신순, `#updatesFilters`, `#updatesList .cms-card`, `.cms-empty-state` (0건/필터 0건/오류/재시도), `#post .cms-post-head`와 본문·메타·날짜.

1. 타이틀은 280ms fade. 카테고리 필터는 선택 상태 밑줄 180ms, 목록에는 짧은 FLIP/reconcile 250–300ms.
2. 게시물 첫 로드 시 최대 앞쪽 5개만 30–40ms 간격(상한 140ms) 등장. **실제 데이터가 늦게 오면 먼저 정직한 loading 상태**, 성공/오류/빈 목록으로 즉시 교체.
3. **NO POSTS YET / NO MATCHES / CONNECTION UNAVAILABLE**를 구분. 메시지는 페이드 때문에 늦게 보이지 않아야 함. 오류의 재시도 버튼은 즉시 반응·disabled 중복 클릭 방지, 성공 후 표시되는 데이터만 소규모 모션.
4. 실제 공지/활동 글 Reader에서는 제목 240–320ms 가벼운 fade, 본문은 즉시 읽을 수 있게 정적. 글의 높이에 따른 실제 스크롤 위치만 진행선으로 표현.
5. 자동 오토스크롤, 알림 토스트 남발, 오래된 오류 메시지가 남는 모션 금지.

## D. 공통 UI·접근성·성능 설계

- 상단 탭 내비게이션: 현재 탭의 밑줄/활성색 180–220ms. 다른 탭으로 진입할 때 **페이지 전체 opacity .35→1 520ms 반복을 240–360ms로 축소**하고 본문 리빌과 중복되지 않게 조정. `navigate`의 해시/뒤로가기/스크롤 기억 그대로.
- 모바일 메뉴: 기존 약 620ms 패널 이동은 240–320ms로 축소 검토, 열린/닫힌 시 aria-expanded/ESC/배경 scrim/포커스 동일. 메뉴 펼침이 콘텐츠를 밀거나 터치 대상을 가리지 않아야 함.
- Footer: 상명대 로고는 장식적 루핑·반짝임 없이 **정적**, SFC 텍스트/링크 역시 정적. 별도 플로팅 버튼, sticky 신규 요소, 큰 배경 그래픽 추가 없음.
- 모션 엔진: 기존 `js/motion.js`의 `play`, `reconcile`, `filterRows`, `controls`, `reveal`을 확장/정리. 일관된 `data-motion` 토큰, 도착 상태와 중단 처리. `js/about-experience.js`/ `js/visual-story.js`/ `js/research-platform.js`는 최소 수정.
- 성능: opacity·transform 위주. 주차 상세는 필요한 경우에만 실제 높이 계산. `blur`, `box-shadow`의 대형 애니메이션, `background-position` 지속 변경, 메인스레드 스크롤 이벤트의 반복 측정 금지. `will-change` 상시 남발 금지.
- 검증: 숨겨진 `.view`/CMS 교체 시 observer 미작동, 앱 비가시 상태 timer 진행, 교차 인터럽트, 브라우저 히스토리·뒤로가기 시 opacity stuck, 재접근 시 안 보이는 콘텐츠 방지.
- 단순 SPA의 모션을 위해 외부 Motion/Rive 등 새 JS 런타임을 추가하지 않음. 기존 CSS/WAAPI 기반으로 구현 가능. 새 의존성은 필요성이 입증될 때만.
