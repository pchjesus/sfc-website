목표: 실제 문서가 도착하기 전에 안전한 작성·복구·편집·가져오기 기반을 구현하고 합성 자료로 검증한다. v3.0 최종 발행과 구분한다. 아래 단계는 계획이며 코드 변경/테스트는 아직 미실행.

## P0 — 기준선 및 재현
- 최신 main에서 별도 feature/sfc-v3.0-preparation 브랜치(이름 제안) 생성. npm test, 기존 quality.yml/Playwright 및 v2.9 시나리오 기준선 확보. js/cms-admin.js, cms-studio.js, cms-core.js, admin.html, css/cms.css, mock fixture 및 기존 테스트 확인.
- 단일 sessionStorage 복구 슬롯, 글 전환·로그아웃·서버 지연·CAS 충돌·오프라인·draft 업로드의 공개 URL 노출 경로를 합성 데이터로 재현. 발견 사항 등급화. 기존 동작이 안전한 부분은 재작성하지 않음.
- 완료: 기준선 결과, 재현 케이스, 실제 파일/DB 불변 기록.

## P1 — S0 저장 안전성
- 글/계정/신규 작업 ID별 session recovery, 타이머 및 최신 snapshot 일관성, 복구 확인, 서버 base version 표시. 새로고침·미완성 본문 보존. 탭 종료 이후 지속 복구는 민감 자료 보안 정책 검토 전 기본 미도입.
- 명확한 저장 중/서버 저장 완료 시각/이 기기만 저장/실패/충돌 상태. 실패 시 입력 유지, 오래된 응답/계정 변경/글 전환 방어. CAS 충돌 자동 덮어쓰기 금지. 중복 생성 위험 재현 및 방지 가능한 범위 수정. 수동 임시저장과 Ctrl/Cmd+S는 절대로 게시하지 않음; 공개 글은 작업본 분리 전 로컬 복구만 허용.
- 공개 sfc-media에 미승인/예약 비공개 파일 업로드 차단 정책 및 명시적 공개 파일 확인. 기본적으로 draft 파일은 업로드하지 않고 로컬 미리보기/재선택 안내; 기존 공개 URL 연결과 게시 취소의 파일 노출 한계 안내. 실제 private bucket/DB 변경은 후속 승인.
- 완료: S-01~S-07/S-10/S-11/S-13 중 해당 mock 사례 PASS, 실패 데이터 보존, 비공개 자료 노출 방지, 별도 실환경 게이트 NOT RUN. 설계상 해결되지 않는 공개본 작업본/고아 파일/실환경 위험은 기록.

## P2 — S1 작성 편의성
- 기존 레이아웃 보존. 저장 상태 상단, sticky 작업 버튼(모바일 안전), 글자 수·제한, 게시물 제목/유형/저자 검색과 기존 상태 필터, 최근 수정 글 재개.
- 안전 렌더러가 지원하는 제목/소제목/목록 중심 툴바, 선택영역 및 Undo/Redo, 빈 본문 템플릿, 붙여넣기. 집중 모드는 레이아웃상 이점 확인 후. 미지원 굵게/표/HTML은 억지로 추가하지 않음.
- 기존 Reader 공용 렌더링 활용한 unsaved preview, 메타/목차/방법/한계 일치, 모바일 미리보기·로컬 PDF 가능 범위. 공개 발행 확인 창(제목/즉시·예약 시간대/공개 승인/파일/누락). 임시저장과 게시 구분.
- 완료: S-08~S-10/S-14/S-15 및 기존 회귀. 기존 7탭 공개 UI와 모션 변경 없음. PC/모바일 조작 시안 제공.

## P3 — RI 0.1~0.3 기반
- 버전 있는 schema, 프롬프트/분석 규칙, 검증 및 필드 매핑 순수 함수, 정상/실패/악성 합성 fixtures, 단위 테스트. 실제 원문이나 API 없음.
- Studio의 '문서로 글 작성' 모달: 분석 지침 복사, JSON 파일/붙여넣기, 오류/누락/근거 검토, 필드 확인 후 신규 임시글 적용. 기존 글/저장 중/취소 보호. 명시적 적용 전 네트워크/DB 변경 없음. 적용 직후 의도치 않은 자동저장을 차단하고 사용자가 임시저장 또는 명시적 자동저장 활성화 선택; 게시 권한 없음.
- Reader 미리보기, 기존 CMS와 필드 연결, 실제 분석 미연결 명시. 원문 첨부 및 외부 AI 이용은 관리자 별도 승인.
- 완료: I-01~I-07 mock/단위 테스트; 실제 자료 분석 품질 I-08 및 API I-09 NOT RUN.

## P4 — 통합 QA 및 소유자 검수
- synthetic TEST ONLY 자료로 신규 초안→편집→미리보기→임시저장→mock 게시→Home/Research/Updates/Reader→비공개/예약/삭제 테스트. 테스트 자료는 운영에 등록하지 않음.
- npm test, 기존 및 추가 Playwright, Actions 결과 기록. 저장/권한/파일 관련 Codex 독립 리뷰, 발견 P0/P1 수정 후 재검증. 360/390/768/1440px, 키보드 및 reduced-motion, 공개 화면 회귀.
- 작업을 작은 검수 단위(PR)로 분리: P1 저장 안전 → P2 UX → P3 Importer → P4 통합. 선행 PR 미병합이면 dependent branch 또는 기준 SHA 명시. 각 PR에 구현/제외/증거/NOT RUN/미해결 위험 및 사용자 미리보기 제시. 명시적 승인 전 main 병합·배포 금지.
- 실제 보고서·실제 계정/DB·비공개 버킷/마이그레이션·AI API·유료 비용·공개 발행은 제외. 보고서 수령 시 schema/하네스 평가 후 v3.0 발행 절차 진행.
